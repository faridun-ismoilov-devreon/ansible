# HAProxy Configuration for ClickHouse Cluster

## Конфигурация добавлена в /etc/haproxy/haproxy.cfg

```haproxy
# ----------  ClickHouse ----------
frontend clickhouse_http
    bind *:8123
    mode tcp
    default_backend clickhouse_http_back

frontend clickhouse_native
    bind *:9000
    mode tcp
    default_backend clickhouse_native_back

backend clickhouse_http_back
    mode tcp
    balance roundrobin
    option tcp-check
    server ch-node-01 192.168.150.140:8123 check
    server ch-node-02 192.168.150.141:8123 check
    server ch-node-03 192.168.150.142:8123 check

backend clickhouse_native_back
    mode tcp
    balance roundrobin
    option tcp-check
    server ch-node-01 192.168.150.140:9000 check
    server ch-node-02 192.168.150.141:9000 check
    server ch-node-03 192.168.150.142:9000 check
```

## Применение изменений

```bash
# Проверить конфигурацию
haproxy -c -f /etc/haproxy/haproxy.cfg

# Перезапустить HAProxy
systemctl restart haproxy

# Проверить статус
systemctl status haproxy
```

## Проверка работы

```bash
# Проверить порты
netstat -tlnp | grep haproxy | grep -E '8123|9000'

# Тест Native протокола (через балансировщик на хосте)
clickhouse-client --host 127.0.0.1 --port 9000 --query "SELECT version(), hostName()"

# Тест HTTP (должен балансировать между нодами)
curl 'http://127.0.0.1:8123/?query=SELECT+hostName()'
curl 'http://127.0.0.1:8123/?query=SELECT+hostName()'
curl 'http://127.0.0.1:8123/?query=SELECT+hostName()'

# С внешнего хоста (замени IP_ХОСТА)
clickhouse-client --host IP_ХОСТА --port 9000 --query "SELECT version()"
curl 'http://IP_ХОСТА:8123/?query=SELECT+1'
```

## Подключение к кластеру через HAProxy

### Через IP хоста (рекомендуется)
```bash
# Native протокол
clickhouse-client --host 37.27.173.224 --port 9000

# HTTP
curl 'http://37.27.173.224:8123/?query=SELECT+1'

# Web UI
http://37.27.173.224:8123/play
```

### Напрямую к нодам (без балансировки)
```bash
clickhouse-client --host 192.168.150.140  # ch-node-01
clickhouse-client --host 192.168.150.141  # ch-node-02
clickhouse-client --host 192.168.150.142  # ch-node-03
```

## Преимущества HAProxy

✅ **Единая точка входа** - один IP для всего кластера
✅ **Автоматическая балансировка** - roundrobin между всеми живыми нодами
✅ **Health check** - если нода упала, трафик не идёт на неё
✅ **Высокая доступность** - если одна нода недоступна, запросы идут на другие

## Мониторинг HAProxy

```bash
# Статистика HAProxy
echo "show stat" | socat stdio /run/haproxy/admin.sock

# Логи
tail -f /var/log/haproxy.log

# Проверить backend статус
echo "show servers state" | socat stdio /run/haproxy/admin.sock | grep clickhouse
```

| 5432 | PostgreSQL | psql |
| 80/443 | OKD Routes | workers |

## Troubleshooting

**Проверить что HAProxy видит ноды как UP:**
```bash
echo "show servers state" | socat stdio /run/haproxy/admin.sock | grep ch-node
```

**Если нода DOWN:**
```bash
# Проверить доступность ноды
telnet 192.168.150.140 8123

# Проверить ClickHouse на ноде
ssh root@192.168.150.140 "systemctl status clickhouse-server"
```

## Обновление конфигурации

Если нужно изменить backend (добавить/удалить ноду):

```bash
# 1. Редактировать конфиг
nano /etc/haproxy/haproxy.cfg

# 2. Проверить
haproxy -c -f /etc/haproxy/haproxy.cfg

# 3. Применить (graceful reload, без разрыва соединений)
systemctl reload haproxy
```
